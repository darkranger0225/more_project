# 小型餐饮门店收银系统开发文档

## 1. 引言

### 1.1 项目背景

小型餐饮门店在日常运营中面临点餐效率低、人工易出错、数据统计困难等问题。传统的手工记账或简单收银工具难以满足一体化管理需求。本项目旨在为小型餐饮门店量身定制一套点餐收银系统，通过数字化手段优化业务流程，提升经营效率。

### 1.2 项目目标

- 实现从顾客点餐、后厨接单、前台收银到经营数据分析的全流程数字化管理。
- 提供直观易用的操作界面，降低员工培训成本。
- 保障数据准确性和系统稳定性，支持日常高频使用。
- 为店主提供基础的营业数据统计，辅助经营决策。

### 1.3 适用范围

本系统适用于小型餐饮门店（如快餐店、小吃店、咖啡厅等），支持单店运营，收银员和管理员两种角色使用。

## 3. 系统架构

系统采用经典的三层架构（表现层、业务层、持久层），遵循MVC设计模式：

- **表现层（Controller）**：处理HTTP请求，调用业务逻辑，通过Thymeleaf渲染视图返回给客户端。
- **业务层（Service）**：封装核心业务逻辑，处理事务。
- **持久层（Repository/DAO）**：与数据库交互，使用Spring Data JPA或MyBatis plus实现数据访问。

系统模块划分：

- 收银员模块：桌台管理、点餐、结算、订单查询。
- 管理员模块：菜品管理、分类管理、桌台配置、员工管理、营业统计、系统设置。

## 4. 功能模块详细设计

### 4.1 角色权限

- **前台收银员**：可使用点餐、结算、查看当日订单等基础功能。
- **后台管理员**：拥有全部功能权限，包括菜品维护、员工管理、数据统计等。

### 4.2 收银员端功能

| 功能     | 描述                                                         |
| :------- | :----------------------------------------------------------- |
| 桌台管理 | 查看桌台状态（空闲/占用），更改桌台状态。                    |
| 点餐下单 | 选择桌台后，浏览菜品分类及菜品，加入购物车，确认后生成订单并推送后厨（给出已推送后厨提示即可）。 |
| 订单结算 | 生成模拟支付二维码（三秒后消失默认成功支付），结算后自动更新桌台状态。逻辑为前台可对选择的桌号进行结账操作 |
| 订单查询 | 按时间、桌台、订单号查询历史订单，可查看详情。               |

### 4.3 管理员端功能

| 功能     | 描述                                                         |
| :------- | :----------------------------------------------------------- |
| 菜品管理 | 菜品的增删改查，包括名称、价格、图片、描述、所属分类、上下架状态。 |
| 分类管理 | 菜品分类（如热菜、凉菜、饮品）的增删改查。                   |
| 桌台配置 | 新增/删除桌台，设置桌台名称、容纳人数、区域。                |
| 员工管理 | 添加/禁用收银员账号，分配角色。                              |
| 营业统计 | 按日/周/月统计营业额、订单数、热门菜品等，以图表形式展示。   |
